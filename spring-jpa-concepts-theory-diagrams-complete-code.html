1. Transactions

Theory: A transaction is a logical unit of work. Successful work is committed; an applicable failure causes rollback.

flowchart TD
A["Business operation"] --> B["BEGIN"]
B --> C["DAO / Repository work"]
C --> D{"Success?"}
D -->|Yes| E["COMMIT"]
D -->|No| F["ROLLBACK"]

Memory: Transaction = one business unit with a commit/rollback boundary.

2. Programmatic Transaction

Theory: Programmatic transaction management means the application code explicitly uses Spring transaction APIs such as TransactionTemplate. The developer controls the transactional callback and can explicitly mark rollback.

flowchart LR
S["Service code"] --> T["TransactionTemplate"]
T --> C["Transactional callback"]
C --> D["DAO"]
D --> DB[("Database")]
T --> R["Commit / Rollback"]

Typical code:

transactionTemplate.execute(status -> {
    try {
        dao.save();
        return null;
    } catch (RuntimeException ex) {
        status.setRollbackOnly();
        throw ex;
    }
});

3. Declarative Transaction

Theory: Declarative transaction management keeps transaction policy outside the business algorithm. You declare the transaction boundary and Spring applies it through transaction infrastructure.

flowchart LR
A["Business method"] --> B["Transaction metadata"]
B --> C["Spring interceptor / proxy"]
C --> D["TransactionManager"]
D --> A

The two styles covered here are XML configuration and @Transactional.

4. Declarative Transaction — XML

Theory: XML configuration can enable Spring transaction interception and connect it to a transaction manager. The service does not need to put transaction metadata directly on the method.

flowchart TD
X["Spring XML"] --> A["Transaction advice"]
A --> P["Spring proxy"]
P --> S["Service"]
A --> T["TransactionManager"]
<tx:annotation-driven transaction-manager="transactionManager"/>

This is the XML infrastructure used by the complete project. More elaborate XML AOP transaction advice can also define pointcuts and transaction attributes explicitly.

5. Declarative Transaction — @Transactional

Theory: @Transactional declares transaction attributes such as propagation, read-only intent, timeout and rollback rules.

sequenceDiagram
participant C as Caller
participant P as Spring Proxy
participant T as TransactionManager
participant S as Service
C->>P: call()
P->>T: begin / join
P->>S: invoke target
S-->>P: result or exception
P->>T: commit / rollback
P-->>C: result

6. PlatformTransactionManager

Theory: PlatformTransactionManager is Spring's common transaction abstraction. Different implementations integrate different transaction technologies.

flowchart TD
P["PlatformTransactionManager"] --> J["JpaTransactionManager"]
P --> D["DataSourceTransactionManager"]
P --> G["JtaTransactionManager"]

7. JpaTransactionManager

Theory: JpaTransactionManager is Spring's transaction manager for a JPA EntityManagerFactory. It coordinates JPA EntityManagers with the transaction.

flowchart LR
T["JpaTransactionManager"] --> F["EntityManagerFactory"]
F --> E["EntityManager"]
E --> PC["Persistence Context"]
PC --> DB[("Database")]

8. Transactional Proxy

Theory: In proxy-based Spring configuration, the caller normally receives a Spring-managed proxy. The proxy starts/joins the transaction, invokes the target method, then commits or rolls back.

sequenceDiagram
participant C as Caller
participant P as Proxy
participant T as TxManager
participant S as Service
C->>P: operation()
P->>T: BEGIN / JOIN
P->>S: operation()
S-->>P: return
P->>T: COMMIT
P-->>C: return
Trap: direct self-invocation such as this.otherTransactionalMethod() can bypass proxy interception.

9. Persistence Context

Theory: A persistence context is the set of entities currently managed by an EntityManager. Managed entity state is tracked and synchronized with persistence.

stateDiagram-v2
[*] --> Transient
Transient --> Managed: persist()
Managed --> Detached: clear / close
Detached --> Managed: merge()
Managed --> Removed: remove()
Removed --> [*]

Memory: Transient → Managed → Detached/Removed.

10. Local Transaction

Theory: A local transaction is associated with one transactional resource, commonly one database.

flowchart LR
A["Application"] --> T["Local transaction manager"] --> DB[("One database")]

11. Global Transaction

Theory: A global/distributed transaction coordinates multiple transactional resources. JTA is the common enterprise transaction abstraction for this model.

flowchart TD
A["Application"] --> T["Global / JTA manager"]
T --> DB["Database"]
T --> MQ["Messaging resource"]
T --> R["Other transactional resource"]

12. Propagation — REQUIRED

Theory: REQUIRED joins an existing transaction or creates a new one when none exists.

flowchart TD
A["Enter method"] --> B{"Transaction exists?"}
B -->|Yes| C["Join existing"]
B -->|No| D["Create new"]
@Transactional(propagation = Propagation.REQUIRED)
public void operation() {
    // Join existing or create a new transaction.
}

13. Propagation — REQUIRES_NEW

Theory: REQUIRES_NEW suspends the current transaction and starts an independent transaction for the invoked method.

sequenceDiagram
participant S as Service
participant A as Tx A
participant B as Tx B
S->>A: main work
A-->>S: suspend
S->>B: BEGIN
B->>B: independent work
B-->>S: COMMIT
S->>A: resume
@Transactional(propagation = Propagation.REQUIRES_NEW)
public void saveAudit() {
    // Independent transaction.
}

14. Propagation — MANDATORY

Theory: MANDATORY requires an existing transaction. It does not create one when the caller has none.

flowchart TD
A["Enter"] --> B{"Existing Tx?"}
B -->|Yes| C["Join"]
B -->|No| D["Reject invocation"]

15. Propagation — NEVER

Theory: NEVER requires that no transaction be active. If one is active, Spring rejects the invocation.

flowchart TD
A["Enter"] --> B{"Transaction exists?"}
B -->|No| C["Execute"]
B -->|Yes| D["Reject"]

16. Propagation — NOT_SUPPORTED

Theory: NOT_SUPPORTED executes without a transaction. An existing transaction is suspended for this method.

sequenceDiagram
participant T as Outer transaction
participant S as Service
T->>S: invoke
S-->>T: suspend
S->>S: non-transactional work
S-->>T: resume

17. Propagation — SUPPORTS

Theory: SUPPORTS participates in the current transaction if one exists; otherwise it can execute without one.

flowchart TD
A["Enter"] --> B{"Transaction exists?"}
B -->|Yes| C["Participate"]
B -->|No| D["Execute without transaction"]

18. Propagation — NESTED

Theory: NESTED represents nested/savepoint behavior where supported. It should not be described simply as an independent transaction.

flowchart TD
A["Outer Tx"] --> B["Savepoint"]
B --> C["Nested work"]
C --> D{"Failure?"}
D -->|No| E["Continue outer"]
D -->|Yes| F["Rollback to savepoint"]

19. Rollback

Theory: Rollback discards transactional database changes that have not been committed, according to the resource/transaction semantics.

flowchart LR
A["BEGIN"] --> B["INSERT / UPDATE"]
B --> C["Failure"]
C --> D["ROLLBACK"]

20. Rollback — RuntimeException

Theory: Spring's default declarative rollback rules normally roll back for unchecked exceptions such as RuntimeException.

@Transactional
public void save() {
    dao.insert();
    throw new RuntimeException("failure");
    // Default rule: rollback.
}

21. Rollback — CheckedException

Theory: A checked exception does not automatically mean rollback under Spring's default rules. Configure rollback explicitly when the business rule requires it.

@Transactional
public void process() throws Exception {
    dao.insert();
    throw new Exception("checked failure");
    // Do not assume rollback by default.
}

22. rollbackFor

Theory: rollbackFor adds specified exception types to the rollback rule.

@Transactional(rollbackFor = Exception.class)
public void process() throws Exception {
    dao.insert();
    throw new Exception("checked failure");
}

23. noRollbackFor

Theory: noRollbackFor excludes specified exception types from rollback rules.

@Transactional(noRollbackFor = WarningException.class)
public void process() {
    dao.insert();
    throw new WarningException("business warning");
}

24. readOnly

Theory: readOnly=true expresses that the transaction is intended for reading and can permit infrastructure/provider optimizations. It is not a universal physical prohibition against every write.

flowchart LR
S["Read service"] --> A["@Transactional(readOnly=true)"]
A --> T["JPA transaction"]
T --> Q["Read operations"]

25. timeout

Theory: A transaction timeout limits how long the transaction may run before the transaction infrastructure can time it out according to the environment.

flowchart LR
A["BEGIN"] --> B["Work"]
B --> C{"Timeout?"}
C -->|No| D["COMMIT"]
C -->|Yes| E["Timeout / rollback outcome"]

26. Spring Data JPA — CrudRepository

Theory: CrudRepository supplies common CRUD operations so you do not implement basic repository boilerplate.

flowchart LR
S["Service"] --> R["CrudRepository"]
R --> I["Generated implementation"]
I --> J["JPA"]
J --> DB[("Database")]

27. Spring Data JPA — RepositoryDefinition

Theory: @RepositoryDefinition lets a repository declare its domain and ID types without extending a Spring Data repository interface. You expose the methods you declare.

@RepositoryDefinition(
    domainClass = EmployeeEntity.class,
    idClass = Integer.class)
public interface EmployeeReadRepository {
    EmployeeEntity findById(Integer id);
}

28. Spring Data JPA — Query Method

Theory: Spring Data derives a query from a repository method name using supported property and operator keywords.

flowchart LR
M["findBySalaryGreaterThanEqualAndRole"] --> P["Parse method name"]
P --> Q["Derived query"]
Q --> J["JPA"]
J --> DB[("Database")]
List<EmployeeEntity>
findBySalaryGreaterThanEqualAndRole(
    Double salary,
    String role);

29. Spring Data JPA — @Query

Theory: @Query lets you provide the JPQL explicitly instead of deriving it from the method name.

@Query("SELECT e FROM EmployeeEntity e WHERE e.salary >= :salary")
List<EmployeeEntity> findEmployees(
    @Param("salary") Double salary);

30. Positional Parameters

Theory: Positional parameters identify query arguments by their position, for example ?1 means the first method parameter.

@Query("SELECT e FROM EmployeeEntity e WHERE e.salary >= ?1")
List<EmployeeEntity> findBySalary(Double salary);
flowchart LR
P["?1"] --> A["First method argument"] --> Q["JPQL binding"]

31. Named Parameters

Theory: Named parameters use a readable placeholder such as :salary and bind it using @Param("salary").

@Query("SELECT e FROM EmployeeEntity e WHERE e.salary >= :salary")
List<EmployeeEntity> findBySalary(
    @Param("salary") Double salary);
flowchart LR
N[":salary"] --> P["@Param('salary')"] --> Q["JPQL binding"]

32. @Modifying

Theory: @Modifying is used with Spring Data JPA @Query methods that perform DML such as UPDATE or DELETE.

@Modifying
@Query("UPDATE EmployeeEntity e SET e.salary = :salary WHERE e.role = :role")
int updateSalary(
    @Param("role") String role,
    @Param("salary") Double salary);
flowchart LR
S["Transactional service"] --> R["Repository"]
R --> M["@Modifying @Query"]
M --> DB[("UPDATE / DELETE")]

33. orm.xml

Theory: META-INF/orm.xml can contain JPA ORM metadata, including named-query definitions. It provides an external location for that metadata.

<entity-mappings xmlns="https://jakarta.ee/xml/ns/persistence/orm" version="3.1">
  <named-query name="Employee.findSeniorEmployees">
    <query>
      SELECT e FROM EmployeeEntity e
      WHERE e.role = 'Senior Developer'
    </query>
  </named-query>
</entity-mappings>
flowchart LR
X["orm.xml"] --> N["Named query"] --> J["JPA provider"] --> DB[("Database")]

11. src/main/java/com/example/employee/dao/EmployeeDAOImpl.java

package com.example.employee.dao;

import com.example.employee.dto.EmployeeDTO;
import com.example.employee.entity.DepartmentEntity;
import com.example.employee.entity.EmployeeEntity;
import jakarta.persistence.EntityManager;
import jakarta.persistence.PersistenceContext;
import org.springframework.stereotype.Repository;
import java.time.LocalDate;
import java.util.List;

@Repository
public class EmployeeDAOImpl implements EmployeeDAO {

    /*
     * Spring injects a container-managed EntityManager.
     * Do not manually call getTransaction().begin().
     */
    @PersistenceContext
    private EntityManager entityManager;

    @Override
    public Integer addEmployee(EmployeeDTO dto) {

        // Convert DTO into the JPA entity.
        EmployeeEntity entity = new EmployeeEntity();
        entity.setName(dto.getName());
        entity.setRole(dto.getRole());
        entity.setSalary(dto.getSalary());
        entity.setJoiningDate(dto.getJoiningDate());

        if (dto.getDepartmentId() != null) {

            // Obtain a managed reference to the department.
            DepartmentEntity department =
                entityManager.getReference(
                    DepartmentEntity.class,
                    dto.getDepartmentId());

            entity.setDepartment(department);
        }

        // New entity becomes managed.
        entityManager.persist(entity);

        return entity.getEmployeeId();
    }

    @Override
    public List<EmployeeEntity> findByJoiningDate(
            LocalDate start, LocalDate end) {

        String jpql = """
            SELECT e
            FROM EmployeeEntity e
            WHERE e.joiningDate BETWEEN :start AND :end
            ORDER BY e.name
            """;

        return entityManager
            .createQuery(jpql, EmployeeEntity.class)
            .setParameter("start", start)
            .setParameter("end", end)
            .getResultList();
    }

    @Override
    public int updateSalaryByRole(
            String role, Double salary) {

        return entityManager.createQuery("""
            UPDATE EmployeeEntity e
            SET e.salary = :salary
            WHERE e.role = :role
            """)
            .setParameter("salary", salary)
            .setParameter("role", role)
            .executeUpdate();
    }

    @Override
    public int deleteByName(String name) {

        return entityManager.createQuery("""
            DELETE FROM EmployeeEntity e
            WHERE e.name = :name
            """)
            .setParameter("name", name)
            .executeUpdate();
    }
}

package com.example.employee.dao;

package com.example.employee.dao;

import com.example.employee.dto.EmployeeDTO;
import com.example.employee.entity.EmployeeEntity;
import org.springframework.stereotype.Component;
import java.time.LocalDate;
import java.util.List;

@Component
public class EmployeeDAOWrapper {

    private final EmployeeDAO dao;

    public EmployeeDAOWrapper(EmployeeDAO dao) {
        this.dao = dao;
    }

    // Wrapper keeps DTO/entity conversion outside the service.
    public Integer addEmployee(EmployeeDTO dto) {
        return dao.addEmployee(dto);
    }

    public List<EmployeeDTO> findByJoiningDate(
            LocalDate start, LocalDate end) {

        return dao.findByJoiningDate(start, end)
            .stream()
            .map(this::toDTO)
            .toList();
    }

    public int updateSalaryByRole(
            String role, Double salary) {
        return dao.updateSalaryByRole(role, salary);
    }

    public int deleteByName(String name) {
        return dao.deleteByName(name);
    }

    private EmployeeDTO toDTO(EmployeeEntity entity) {

        EmployeeDTO dto = new EmployeeDTO();
        dto.setEmployeeId(entity.getEmployeeId());
        dto.setName(entity.getName());
        dto.setRole(entity.getRole());
        dto.setSalary(entity.getSalary());
        dto.setJoiningDate(entity.getJoiningDate());

        if (entity.getDepartment() != null) {
            dto.setDepartmentId(
                entity.getDepartment().getDepartmentId());
        }

        return dto;
    }
}

package com.example.employee.repository;

import com.example.employee.entity.EmployeeEntity;
import org.springframework.data.jpa.repository.*;
import org.springframework.data.repository.CrudRepository;
import org.springframework.data.repository.query.Param;
import java.util.List;

public interface EmployeeRepository
        extends CrudRepository<EmployeeEntity, Integer> {

    // Query Method: Spring Data derives the query.
    List<EmployeeEntity>
    findBySalaryGreaterThanEqualAndRole(
        Double salary, String role);

    // Positional parameter: ?1 = first argument.
    @Query("""
        SELECT e
        FROM EmployeeEntity e
        WHERE e.salary >= ?1
        """)
    List<EmployeeEntity> findByMinimumSalary(
        Double salary);

    // Named parameter: :salary -> @Param("salary").
    @Query("""
        SELECT e
        FROM EmployeeEntity e
        WHERE e.salary >= :salary
        """)
    List<EmployeeEntity> findByMinimumSalaryNamed(
        @Param("salary") Double salary);

    // UPDATE requires @Modifying.
    @Modifying
    @Query("""
        UPDATE EmployeeEntity e
        SET e.salary = :salary
        WHERE e.role = :role
        """)
    int updateSalaryByRole(
        @Param("role") String role,
        @Param("salary") Double salary);

    // DELETE also requires @Modifying.
    @Modifying
    @Query("""
        DELETE FROM EmployeeEntity e
        WHERE e.name = :name
        """)
    int deleteByName(@Param("name") String name);

    // Named query stored in META-INF/orm.xml.
    @Query(name = "Employee.findSeniorEmployees")
    List<EmployeeEntity> findSeniorEmployees();
}

package com.example.employee.service;

import com.example.employee.dao.DepartmentDAO;
import com.example.employee.dao.EmployeeDAOWrapper;
import com.example.employee.dto.DepartmentDTO;
import com.example.employee.dto.EmployeeDTO;
import com.example.employee.repository.EmployeeRepository;

import org.springframework.stereotype.Service;
import org.springframework.transaction.PlatformTransactionManager;
import org.springframework.transaction.support.TransactionTemplate;
import org.springframework.transaction.annotation.*;

import java.time.LocalDate;
import java.util.List;

@Service
public class EmployeeServiceImpl
        implements EmployeeService {

    private final EmployeeDAOWrapper employeeDAO;
    private final DepartmentDAO departmentDAO;
    private final EmployeeRepository repository;

    /*
     * Programmatic transaction support.
     * We depend on Spring's common transaction abstraction.
     */
    private final TransactionTemplate transactionTemplate;

    public EmployeeServiceImpl(
            EmployeeDAOWrapper employeeDAO,
            DepartmentDAO departmentDAO,
            EmployeeRepository repository,
            PlatformTransactionManager transactionManager) {

        this.employeeDAO = employeeDAO;
        this.departmentDAO = departmentDAO;
        this.repository = repository;

        this.transactionTemplate =
            new TransactionTemplate(transactionManager);
    }

    @Override
    @Transactional
    public Integer addEmployee(EmployeeDTO dto) {

        validate(dto);

        return employeeDAO.addEmployee(dto);
    }

    @Override
    @Transactional(readOnly = true)
    public List<EmployeeDTO> findEmployees(
            LocalDate start, LocalDate end) {

        return employeeDAO.findByJoiningDate(
            start, end);
    }

    @Override
    @Transactional
    public int updateSalaryByRole(
            String role, Double salary) {

        return repository.updateSalaryByRole(
            role, salary);
    }

    @Override
    @Transactional
    public int deleteByName(String name) {
        return repository.deleteByName(name);
    }

    /*
     * REQUIRED is the normal/default propagation.
     * Both DAO operations participate in this transaction.
     */
    @Override
    @Transactional(propagation = Propagation.REQUIRED)
    public void createDepartmentWithEmployee(
            String departmentName,
            EmployeeDTO employee) {

        Integer departmentId =
            departmentDAO.addDepartment(
                new DepartmentDTO(departmentName));

        employee.setDepartmentId(departmentId);

        employeeDAO.addEmployee(employee);

        /*
         * Uncomment to demonstrate rollback of BOTH operations:
         *
         * throw new RuntimeException("Demo failure");
         */
    }

    /*
     * PROGRAMMATIC TRANSACTION:
     * No @Transactional is required for this method.
     * The code explicitly executes a transactional callback.
     */
    @Override
    public void demonstrateProgrammaticTransaction(
            EmployeeDTO employee) {

        transactionTemplate.execute(status -> {

            try {

                employeeDAO.addEmployee(employee);

                // Additional DAO operations can be included here.

                return null;

            } catch (RuntimeException ex) {

                // Explicit programmatic rollback request.
                status.setRollbackOnly();

                throw ex;
            }
        });
    }

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void requiresNewOperation() {
        // Suspend outer transaction and start a new one.
    }

    @Transactional(propagation = Propagation.MANDATORY)
    public void mandatoryOperation() {
        // Transaction must already exist.
    }

    @Transactional(propagation = Propagation.NEVER)
    public void neverOperation() {
        // Transaction must not exist.
    }

    @Transactional(propagation = Propagation.NOT_SUPPORTED)
    public void notSupportedOperation() {
        // Suspend outer transaction and execute without one.
    }

    @Transactional(propagation = Propagation.SUPPORTS)
    public void supportsOperation() {
        // Participate if a transaction exists.
    }

    @Transactional(propagation = Propagation.NESTED)
    public void nestedOperation() {
        // Savepoint/nested semantics where supported.
    }

    @Transactional(rollbackFor = Exception.class)
    public void checkedExceptionRollback()
            throws Exception {

        employeeDAO.addEmployee(new EmployeeDTO());

        // Explicit rollback rule for checked exception.
        throw new Exception("Checked failure");
    }

    @Transactional(noRollbackFor = WarningException.class)
    public void warningExample() {

        employeeDAO.deleteByName("demo");

        // Configured not to trigger rollback by this rule.
        throw new WarningException();
    }

    private void validate(EmployeeDTO dto) {

        if (dto == null ||
            dto.getName() == null ||
            dto.getName().isBlank()) {

            throw new IllegalArgumentException(
                "Employee name is required");
        }
    }

    public static class WarningException
            extends RuntimeException {
    }
}

package com.example.employee;

import com.example.employee.dto.EmployeeDTO;
import com.example.employee.service.EmployeeService;

import org.springframework.context.support.ClassPathXmlApplicationContext;

import java.time.LocalDate;

public class Application {

    public static void main(String[] args) {

        /*
         * Spring creates:
         * Service -> Proxy -> DAO/Repository
         * plus EntityManagerFactory and TransactionManager.
         */
        try (ClassPathXmlApplicationContext context =
                new ClassPathXmlApplicationContext(
                    "applicationContext.xml")) {

            EmployeeService service =
                context.getBean(EmployeeService.class);

            EmployeeDTO employee =
                new EmployeeDTO();

            employee.setName("Rahul");
            employee.setRole("Backend Developer");
            employee.setSalary(75000.0);
            employee.setJoiningDate(LocalDate.now());

            // Declarative transaction through @Transactional.
            Integer id = service.addEmployee(employee);

            System.out.println(
                "Created employee ID = " + id);

            /*
             * One business transaction containing:
             * 1. INSERT department
             * 2. INSERT employee
             *
             * Uncomment the RuntimeException inside the
             * service to observe rollback behavior.
             */
            EmployeeDTO second =
                new EmployeeDTO();

            second.setName("Transaction Demo");
            second.setRole("Developer");
            second.setSalary(60000.0);
            second.setJoiningDate(LocalDate.now());

            service.createDepartmentWithEmployee(
                "Engineering", second);

            /*
             * readOnly transaction.
             */
            var employees =
                service.findEmployees(
                    LocalDate.of(2026, 1, 1),
                    LocalDate.of(2026, 12, 31));

            employees.forEach(e ->
                System.out.println(
                    e.getName() + " | " +
                    e.getRole() + " | " +
                    e.getSalary()));

            /*
             * Programmatic transaction.
             */
            EmployeeDTO third =
                new EmployeeDTO();

            third.setName("Programmatic Demo");
            third.setRole("Developer");
            third.setSalary(65000.0);
            third.setJoiningDate(LocalDate.now());

            service.demonstrateProgrammaticTransaction(
                third);
        }
    }
}

MANDATORY     = transaction must already exist
NEVER         = transaction must not exist
NOT_SUPPORTED = suspend transaction
SUPPORTS      = participate if available
NESTED        = savepoint/nested semantics where supported

RuntimeException = rollback by default
CheckedException = do not assume rollback
rollbackFor      = add rollback rule
noRollbackFor    = exclude rollback rule
